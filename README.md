# PortfolioViz

The commits recorded as `=` run from 2024-06-27 through 2024-07-16. `LoadMarketData.py` and `test.py` are the June 27 commit. `MarketCalculations.py` was added on 2024-07-01, `javascript.js` on 2024-07-11, and the Dash apps on 2024-07-16. Every connection uses user `root`, database `PortfolioVisualizer`, and an empty password. The Python scripts use host `127.0.0.1`. The Express server uses host `localhost`.

`scripts/LoadMarketData.py` connects to MySQL before any download. A refused connection stops the script there. `datetime` is imported and not used. It then downloads AAPL, MSFT, and GOOG with `start="2023-01-01"` and `end="2023-12-31"`. yfinance treats `end` as exclusive, so 2023-12-31 is not requested. In yfinance 1.8.0, `download` defaults to `multi_level_index=True`, so `row['Close']` is a one-element Series. That Series is the `VALUE` the insert sends. `download` also defaults to `auto_adjust=True`, so that Close is the adjusted close, not the unadjusted close. `Ticker.history` defaults to the same flag, and it adjusts the open as well, so the holding-period return uses those adjusted prices. The row's index is still passed through, rather than a formatted string. Those inserts are committed before the next loop. It then loads `period="1y"` of history for those three symbols. Holding-period return is (close − open) / open. With the numpy float64 prices from `Ticker.history`, an open of 0 makes that return infinity when the close is positive, negative infinity when the close is negative, and NaN when the close is also 0. The other columns stay at that day's close. Every other column in that insert, including market value, Sharpe, Treynor, Jensen, PE, ROA, ROE, and the margins, is set to that close. The `Market_Calculations` insert has no date and no symbol, so a row does not say which day or which of the three symbols it came from. `MarketCalculations.py` and `GET /market_calculations` use `PORTFOLIO_CALCULATIONS`, so they do not read these rows. A failure in that second loop leaves the `MARKET_DATA` rows committed and does not close the connection. A failure in the first loop, before that first commit, leaves the `MARKET_DATA` rows uncommitted and does not close the connection. When the second loop finishes, it commits `Market_Calculations`, then calls `cursor.close()` and `cnx.close()`.

`scripts/MarketCalculations.py` reads distinct symbols from `TRANSACTIONS`. The `MARKET_DATA` insert downloads each symbol with `start="2023-01-01"` and `end="2023-12-31"`. In yfinance 1.8.0, `download` defaults to `multi_level_index=True`, so `row['Close']` is a one-element Series and that Series is the stored `VALUE`. `download` also defaults to `auto_adjust=True`, so that Close is the adjusted close. `Ticker.history` defaults to the same flag, so the stock's close-to-close returns and the holding-period return use adjusted prices. The SPY download is adjusted the same way. Beta uses a different pair: that symbol's trailing `period="1y"` close-to-close returns against SPY's close-to-close returns for the same 2023 arguments. Both indexes are sent through `tz_localize(None)` before the dates are joined. On pandas 3.1.1 a naive index stays naive and does not raise. Those SPY returns are a one-column DataFrame, so building the joined frame raises `ValueError: Data must be 1-dimensional`, with the array shape `(n, 1)`, where n is the number of SPY returns left after `dropna`. The length check and `linregress` are not reached. If the market returns were a Series, the length check after the join could not fail, because both columns come from the same dropped frame. `linregress` would be called with the market series first and the stock series second, so the slope would be the stock return on the market return. Fewer than two aligned rows would make that call raise `ValueError`. The `MARKET_DATA` rows are already committed, `PORTFOLIO_CALCULATIONS` is not committed, and the connection is not closed. The `MARKET_DATA` date is formatted with `%Y-%m-%d`, unlike `LoadMarketData.py`. The rows written to `PORTFOLIO_CALCULATIONS` are the trailing year, not the 2023 download, and that date is also formatted with `%Y-%m-%d`. For each of those days the dividend is 0, so HPR, TMW, and RAR are the same number, (close − open) / open. With the numpy float64 prices from `Ticker.history`, an open of 0 makes that number infinity when the close is positive, negative infinity when the close is negative, and NaN when the close is also 0. Sharpe divides that return minus 0.03 by the standard deviation of the trailing close-to-close returns. That deviation is `stock_returns.std()`, and pandas' default `ddof` is 1, including in pandas 3.1.1, so the divisor is one less than the number of those returns. One return makes the deviation NaN. It is computed once per symbol and reused for every inserted day, including the first day, whose own percent change was dropped from that series. A zero standard deviation stores Sharpe as 0. That test is `!= 0`, and a NaN standard deviation passes it, so the division still runs and Sharpe is NaN. Treynor divides the same numerator by beta. A zero beta stores Treynor as 0. A NaN beta also passes `!= 0`, so Treynor is NaN. Jensen's alpha is that return minus 0.03, minus beta times the mean of the 2023 SPY close-to-close returns minus 0.03. Before each insert it prints `Executing SQL:` and the statement with the values already substituted. The `execute` call still sends the placeholders. PE, ROA, ROE, and the margins come from `Ticker.info`. One missing key sets all five to NaN. Another exception is not caught. The style score is `numpy.random.random()`, drawn again for every inserted day. Every inserted row uses account id 1. Account value is that day's close. `TMW` and `RAR` are both the holding-period return. A download or insert error before the first `cnx.commit()` leaves those `MARKET_DATA` rows uncommitted and does not close the connection. The second commit, `cursor.close()`, and `cnx.close()` run only after every symbol's calculation inserts finish. An empty `TRANSACTIONS` symbol list still reaches that commit and those closes, and it never calls `calculate_beta`.

`scripts/app.py`, `scripts/dash.py`, and `scripts/dash_app.py` are the same 156 bytes. The layout is an `html.Div` whose children are the text "Hello World". Importing a file creates that app and does not start it. `app.run_server(debug=True)` runs only when the file is the main program, and the call passes no host and no port.

`scripts/MarketCalculationsTest.py` downloads AAPL, MSFT, and GOOG with `start="2023-01-01"` and `end="2023-12-31"`, then calls `cursor.execute`. `cursor` and `cnx` are never created, so a download that has rows stops with `NameError` on `cursor`. Python looks up `cursor` before it evaluates the arguments, so `date.strftime('%Y-%m-%d')` does not run. An empty download never calls `execute` and stops with `NameError` on `cnx.commit()`. The lines after that are not reached. They call `calculate_beta(stock_returns, market_returns)` before either name exists. That function, unlike `MarketCalculations.py`, divides the covariance of the two series by the variance of the market series, after keeping only the tail of the longer series. That cut is by position, before the dates are aligned. One shared row, or none, makes the covariance NaN, so the returned beta is NaN. When the market variance is exactly 0, the covariance is also 0 and that division returns NaN. It does not raise. On pandas 3.1.1 a three-row market series of 0.05 has variance about 7.22e-35, not 0. When both indexes have a timezone, it calls `tz_convert(None)` on both, which converts them to UTC and then drops the zone. When only one index has a timezone, it calls `tz_localize(None)` on that side, which drops the zone and keeps the clock time. `pandas` is imported four times. The three imports after `cnx.commit()` are not executed when the script stops on `cursor` or `cnx`. `pd.Series` on the one-column SPY frame that later loop would build raises `ValueError: Cannot construct a Series from a DataFrame. To select a single column, use df.iloc[:, 0].` before the tail cut. That call is not reached. The example call would print `beta_p`. The symbol loop would print `Before alignment: ` plus the symbol and the two lengths. After that loop, `print(market_returns.head())` would print the last symbol's SPY returns. None of those lines run. `linregress`, `datetime`, and `mysql.connector` are imported and unused. The later loop computes the same Sharpe, Treynor, and Jensen figures as `MarketCalculations.py` and does not insert them.

`scripts/javascript.js` is an Express server on port 3000 with CORS enabled for every origin. A failed MySQL connection is logged and the process still listens. The listen line does not wait for that connection, so `Server is running on http://localhost:3000` can print before `Connected to MySQL`. The only registered route is `GET /market_calculations`. It runs `SELECT * FROM PORTFOLIO_CALCULATIONS`. A query error returns HTTP 500 and `{ "error": "Error fetching data" }`. A successful query returns the raw row array. `scripts/test.py` selects every row from `TRANSACTIONS` and prints each row. `yfinance` and `datetime` are imported and unused, and `mysql.connector` is imported three times. Any `mysql.connector.Error`, including a query error after the connection is open, prints `Error while connecting to MySQL`. If that error happens before `cnx` is assigned, the `finally` block raises `NameError` and does not print the closed line. If `connect` succeeds and `cursor()` raises `mysql.connector.Error`, `cnx` is assigned and `cursor` is not. The `finally` block then raises `NameError` on `cursor.close()`, the closed line is not printed, and the connection is not closed. `Error` is imported twice. If `cnx` was assigned and `is_connected()` is true, including a successful select, it closes the connection and prints `MySQL connection is closed`. If `cnx` is assigned and `is_connected()` is false, it does not close the connection and does not print that line. `scripts/SQL.sql` runs `SHOW DATABASES`, `USE PortfolioVisualizer`, and `SHOW TABLES`. It does not create the database or a table.
