# PortfolioViz

The commits recorded as `=` run from 2024-06-27 through 2024-07-16. `LoadMarketData.py` and `test.py` are the June 27 commit. `MarketCalculations.py` was added on 2024-07-01, `javascript.js` on 2024-07-11, and the Dash apps on 2024-07-16. Every connection uses user `root`, database `PortfolioVisualizer`, and an empty password. The Python scripts use host `127.0.0.1`. The Express server uses host `localhost`.

`scripts/LoadMarketData.py` connects to MySQL before any download. A refused connection stops the script there. It then downloads AAPL, MSFT, and GOOG with `start="2023-01-01"` and `end="2023-12-31"`. It inserts the close into `MARKET_DATA` and passes the row's index through, rather than a formatted string. Those inserts are committed before the next loop. It then loads `period="1y"` of history for those three symbols. Holding-period return is (close − open) / open. Every other column in that insert, including market value, Sharpe, Treynor, Jensen, PE, ROA, ROE, and the margins, is set to that close. The `Market_Calculations` insert has no date and no symbol, so a row does not say which day or which of the three symbols it came from. A failure in that second loop leaves the `MARKET_DATA` rows committed and does not close the connection.

`scripts/MarketCalculations.py` reads distinct symbols from `TRANSACTIONS`. The `MARKET_DATA` insert downloads each symbol with `start="2023-01-01"` and `end="2023-12-31"` and stores the close. Beta uses a different pair: that symbol's trailing `period="1y"` close-to-close returns against SPY's close-to-close returns for the same 2023 arguments. Both indexes are sent through `tz_localize(None)` before the dates are joined, including an index that is already naive. `linregress` is called with the market series first and the stock series second, so the slope is the stock return on the market return. The `MARKET_DATA` date is formatted with `%Y-%m-%d`, unlike `LoadMarketData.py`. The rows written to `PORTFOLIO_CALCULATIONS` are the trailing year, not the 2023 download, and that date is also formatted with `%Y-%m-%d`. For each of those days the dividend is 0, and the holding-period return is (close − open) / open. Sharpe divides that return minus 0.03 by the standard deviation of the trailing close-to-close returns. A zero standard deviation stores Sharpe as 0. Treynor divides the same numerator by beta. A zero beta stores Treynor as 0. Jensen's alpha is that return minus 0.03, minus beta times the mean of the 2023 SPY close-to-close returns minus 0.03. Before each insert it prints `Executing SQL:` and the statement with the values already substituted. The `execute` call still sends the placeholders. PE, ROA, ROE, and the margins come from `Ticker.info`, or NaN when a key is missing. Another exception is not caught. The style score is `numpy.random.random()`. Every inserted row uses account id 1. Account value is that day's close. `TMW` and `RAR` are both the holding-period return.

`scripts/app.py`, `scripts/dash.py`, and `scripts/dash_app.py` are the same Dash app. The layout text is "Hello World", and `app.run_server(debug=True)` starts it.

`scripts/MarketCalculationsTest.py` downloads AAPL, MSFT, and GOOG with `start="2023-01-01"` and `end="2023-12-31"`, then calls `cursor.execute`. `cursor` and `cnx` are never created, so a download that has rows stops with `NameError` on `cursor`. An empty download never calls `execute` and stops with `NameError` on `cnx.commit()`. The lines after that are not reached. They call `calculate_beta(stock_returns, market_returns)` before either name exists. That function, unlike `MarketCalculations.py`, divides the covariance of the two series by the variance of the market series, after keeping only the tail of the longer series. A zero market variance divides by zero. When both indexes have a timezone, it calls `tz_convert(None)` on both, which converts them to UTC and then drops the zone. When only one index has a timezone, it calls `tz_localize(None)` on that side, which drops the zone and keeps the clock time. `pandas` is imported four times. `linregress`, `datetime`, and `mysql.connector` are imported and unused. The later loop computes the same Sharpe, Treynor, and Jensen figures as `MarketCalculations.py` and does not insert them.

`scripts/javascript.js` is an Express server on port 3000 with CORS enabled for every origin. A failed MySQL connection is logged and the process still listens. The listen line does not wait for that connection, so `Server is running on http://localhost:3000` can print before `Connected to MySQL`. `GET /market_calculations` runs `SELECT * FROM PORTFOLIO_CALCULATIONS`. A query error returns HTTP 500 and `{ "error": "Error fetching data" }`. `scripts/test.py` selects every row from `TRANSACTIONS` and prints each row. `yfinance` and `datetime` are imported and unused, and `mysql.connector` is imported three times. A connection error prints `Error while connecting to MySQL`. The `finally` block then reads `cnx`, which was never assigned, so that failure becomes a `NameError`. A path that does get a connection, including a successful select, prints `MySQL connection is closed`. `scripts/SQL.sql` runs `SHOW DATABASES`, `USE PortfolioVisualizer`, and `SHOW TABLES`.
